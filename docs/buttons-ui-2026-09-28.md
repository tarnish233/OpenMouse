# 按键页 UI 整理 — 2026-09-28

## 范围

仅调整 SwiftUI 呈现与文案，不改映射持久化格式、动作执行、鼠标录入回调、DPI 缓存或 HID++ 读写链路。发布目标为 0.7.9 (19)。发布流程不安装覆盖本机正式应用。

- 标题区显示映射数量；有映射时将「录入按键」提升为右侧主操作，空状态只保留一个录入入口。
- 每行保持「按键徽标 → 动作菜单 → 删除」的对齐；修饰键在徽标内单独一行，不拉宽整列。
- 动作菜单占满动作列，DPI、快捷键、应用选择等附加参数排在下方，不再挤占主行。
- DPI 分为档位一/二，保留原先的有序取值限制；当前数值独立显示，当前档位使用浅色强调。未知读数不在视觉或无障碍标签中冒充“当前/未使用”。
- 手势动作提供操作提示；较长的录入说明收进可展开帮助。
- 工具栏无草稿时显示中性的「✓ 已保存」，有草稿时才显示蓝色「保存」，保留 ⌘S。

## macOS 菜单注意事项

在本机 macOS 27 的实机预览中，`.borderlessButton` 菜单会将自定义标签抽取为原生标题/图标，丢失 HStack 的宽度和箭头位置。改为 `.menuStyle(.button)` + `.buttonStyle(.plain)`，保留 SwiftUI 标签布局，同时仍使用系统 Menu 和分组子菜单。箭头仅作装饰，不重复向辅助功能暴露。

## 验证

使用固定签名的 `Open Mouse Debug.app`；测试前备份完整 Debug 配置并关闭其 enabled 和自动更新，不与正式应用竞争输入接管。

- `make debug`：通过，SDK 27.0 / 最低 macOS 14.0 元数据与签名检查通过。
- `make test`：应用 535 项、更新助手、6 项发布签名、16 项社区签名、26 项构建元数据检查全部通过。
- 实际窗口视觉检查（700pt 宽）：三个常用映射、组合键包含 fn/⌃/⌥/⇧/⌘、未设置快捷键、长应用名、400/4000 DPI 边界值均未挤压动作列或删除按钮。
- DPI 菜单展开、选择 800 DPI：显示和草稿状态正确，菜单仍限制低档小于高档。
- 有草稿时切换侧栏弹出保存确认，取消后仍留在按键页并保留草稿；保存按钮能回到中性状态。
- 局部快捷键录制 ⇧⌘K、随后 ⌘S 保存：通过。
- 动作菜单分组仍完整；帮助展开、空列表单一录入入口：通过。
- 最后终止测试进程，将 Debug 配置逐字节恢复；正式应用及 Karabiner 配置的 SHA-256 与测试前一致。

## 验证边界

本次不接管实体鼠标，未打开鼠标按键录入模式，也未写入硬件 DPI。因此实际当前 DPI 高亮由已有读数/档位逻辑决定，不能把本次 UI 检查说成重新完成了硬件兼容性验证。未实机覆盖 macOS 14–26 或深色外观。

# 按键页 DPI 缓存与异步刷新回归（2026-09-28）

## 证据与范围

环境：macOS 27.0、Xcode 27、Bluetooth Logi M750 L（046D/B02C）。
正式版 0.7.7 的只读线程采样中，反复切页捕获以下调用链：

`ButtonsSettingsPane.onAppear → LogitechHIDPPManager.refreshDPI → IOHIDDeviceSetReport → IOConnectCallMethod → mach_msg2_trap`

1 ms 间隔的 30 秒采样中，这条同步调用链占 365 个样本。样本数不等同于精确的单次页面加载时间；只能证明切页渲染中确实在等待同步设备 IO。

不缓存整个 SwiftUI 页面或用户草稿，不修改侧栏导航/未保存确认。复用 MouseEngine 已有的可观察 DPI 值，只添加设备会话级的新鲜度缓存和异步硬件请求。

## 实现约束

- 成功响应后缓存 10 秒；重复进入不读取硬件。
- 缓存过期仍先显示上次值；使用 Apple `IOHIDDeviceSetReportWithCallback` 提交查询，不阻塞等待蓝牙回复，也不使用同步兜底。
- DPI 发现、读取和切换写入都使用异步 API。发送成功不代表硬件设置成功，仍等 HID++ 输入响应才发布 DPI 值。
- 真正的 DPI 切换不使用缓存决定目标值；仍先读取硬件。正在读取时的 DPI 按键沿用已有的“升级为切换”逻辑。
- 在途查询由 DPI 状态机合并；请求 ID 和阶段检查防止迟到的异步错误终止后来的请求。
- 失败后退避 5 秒；明确不支持 DPI 的会话不重复发现。停止/断线清除会话；重连重新发现。
- 异步报告独立持有字节和回调到完成/取消；提交失败立即释放；不持有设备，避免阻止其 unschedule/close。
- 普通 HID++ 控件发现/接管仍沿用原路径，本次没有重写整个 HID 子系统。

依据：本机 SDK 的 `IOKit/hid/IOHIDDevice.h`，以及 Apple IOKitUser 的 `hid.subproj/IOHIDDevice.c`（SetReportWithCallback 的同步拒绝与异步 abort 生命周期）。

## 验证

### 自动检查

`make test`：489 项应用检查（新增 27 项）通过；更新助手、6 项发布签名、16 项社区签名、26 项 SDK 元数据检查通过。新增覆盖冷缓存、10 秒边界、读写成功刷新、失败退避、时钟回退、不支持设备、重连，以及异步缓冲区的成功/取消/提交失败生命周期。

### 真实鼠标只读探针

使用签名的独立 Debug 包，通过临时 main 入口运行实际 LogitechHIDPPManager；不创建事件 tap、不提供任何期望绑定、不写 DPI、不载入偏好设置。探针入口已移除并重建最终 Debug 包。

- 首次发现收到 `1000 DPI`。
- 缓存内三次刷新入口耗时：0.0142、0.0060、0.0057 ms。
- 11 秒后缓存过期，异步提交入口耗时：0.2935 ms。
- 5 ms 后重复刷新入口耗时：0.0098 ms；在途请求被复用。
- HID++ 日志只有首次读取和过期刷新两次 `current DPI=1000`，后者正常返回。
- 10 ms 主循环心跳在设备发现完成后测到的最大间隔为 30.71 ms；该数据只是单次本机探针结果，不是 UI 帧率或整页加载时间基准。

### UI 回归与边界

最终 Debug 包暂时禁用独立输入引擎，按“滚动 → 按键 → 指针 → 按键 → 通用 → 按键”切换；内容、标题和选中项一致，映射和 DPI 编辑菜单正常显示，没有异常确认框。正式版保持运行，不接管其鼠标。测试后退出 Debug 并还原 Debug 偏好。

本轮没有操作物理 DPI 切换键、拔插鼠标或模拟蓝牙断线：这些仍需发布前的硬件回归；纯逻辑/内存生命周期自检不声称替代此验证。没有修改版本号、发布 GitHub Release 或替换 /Applications 中的正式版。

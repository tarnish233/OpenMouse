# 设置离开确认回归验证（2026-09-28，v0.7.7）

## 现场与修复边界

macOS 27.0（26A428）上，v0.7.6 有未保存修改时点击侧栏，出现新页高亮而正文仍在旧页的假死。两次进程采样均落在 `SettingsNavigation.selectedTab.setter → SettingsLeaveConfirmation.confirm → NSAlert.runModal`；同时仍有 Logitech 输入回调，不是 HID++ 发送请求阻塞。

改为下一轮主队列呈现设置窗口所属的 `beginSheetModal`，在 sheet 完成回调返回 AppKit 后再处理决定并继续原动作。切页、历史导航、关窗、退出共享单请求协调器，重复请求与迟到回复不能影响其他动作。保留保存 / 不保存 / 取消语义，不强制丢弃草稿。

## 真实 UI 操作

使用独立 `Open Mouse Debug.app`（独立 bundle ID 与配置目录），先备份 Debug 配置；测试期间总开关停用、自动更新关闭，不让测试进程接管鼠标。

| 路径 | 验证结果 |
| --- | --- |
| 修改滚动设置 → 按键页 → 取消 | 确认框可见；保留修改，正文和高亮均回到滚动页 |
| 同一草稿重新切页 → 保存 | 重新弹出确认，保存后才进入按键页且显示已保存 |
| 修改 M750 L 指针选项 → 按键页 | 实际确认框可见；取消保留设备草稿，保存后正文/标题/高亮一致 |
| 修改 M750 L 指针选项 → 不保存 | 恢复已保存选项再切页；返回指针页确认恢复结果 |
| 指针草稿 → 返回历史 → 取消 / 不保存 | 取消不移动历史，确认后才返回；前向历史保留 |
| 草稿 → 关闭窗口 → 取消 / 不保存 / 保存 | 取消保留草稿；允许关闭时产生 `settings window closed`，重开后的设置与选择一致 |
| 草稿 → ⌘Q → 取消 / 不保存 / 保存 | 取消产生 `deferred termination reply: false` 并保留修改；允许退出产生 `true`，进程确实退出；重启核对保存结果 |

注意：自动化读取关闭后的窗口可能仍返回窗口状态，因此关窗结果同时用 `windowWillClose` 生命周期日志和重开后的保存状态交叉验证，不能只凭最后一张窗口截图判断。

测试结束后停止 Debug 进程并恢复原 Debug 配置。正式配置和 Karabiner 映射按测试前后的 SHA-256 核对一致；正式进程中的未保存草稿未被保存、丢弃或强制终止。

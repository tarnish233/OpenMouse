# 保存状态与工具栏文案修正 — 2026-09-28

## 问题

v0.7.9 将 `!hasUnsavedChanges` 直接呈现为「✓ 已保存」。这把首次加载、撤销草稿、即时设置自动落盘和明确保存混为一谈；工具栏中的 Label 图标还挤占了文字空间。

## 修正

- 右上角统一使用纯文字 Button，不再包含勾图标，保留系统按钮内边距并避免文字横向压缩。
- `SettingsStore.SaveState` 区分 unchanged / modified / saved。
- 新编辑会话：禁用的「保存」。有草稿：可用的蓝色「保存」。本次会话明确执行保存后：禁用的「已保存」。
- 再次修改会清除旧保存反馈；手动改回原值、撤销、即时提交、关闭后重开都不冒充一次新的保存。
- 即时设置的自动落盘不产生保存反馈，也不抹去仍有效的本次草稿保存记录；已有窗口重新聚焦不重置会话。
- 文案帮助区分「没有需要保存的修改」与「本次修改已保存」。保留 ⌘S 及原有异步离开确认流程。

## 验证

- 新增 19 项针对真实隔离 SettingsStore 的回归断言；使用临时文件，不启动工作区观察、鼠标引擎或触碰正式配置。
- `make test`：554 项应用自检、更新助手、6 项发布签名、16 项社区签名及 26 项构建元数据检查通过。
- `make debug`：固定签名与 SDK / 最低系统元数据检查通过。
- 隔离 Debug 界面验证：初次打开为灰色保存；修改后启用；点击保存及 ⌘S 后才显示纯文字已保存；再次修改后恢复保存；撤销后为灰色保存；关闭已保存窗口并重开后恢复灰色保存。
- 在与反馈截图相同的通用页核对右上角布局：无勾图标、无文字裁切。
- v0.7.10（20）发布前再次验证切页、返回、关闭窗口、退出应用四类离开操作，各自的保存 / 不保存 / 取消共 12 条路径；取消保留草稿，不保存恢复基线，保存写入；关闭再打开时重置为灰色保存。
- 社区发布包通过解压后的严格签名校验、554 项自检与更新助手自检；已安装 v0.7.9 的更新助手确认新包满足相同指定签名要求。
- 测试过程保持 Debug 输入接管关闭；结束后终止测试进程并逐字节恢复 Debug 原配置。正式应用和 Karabiner 配置哈希不变。

发布目标为 v0.7.10（20）；不改变配置结构、鼠标事件处理、DPI 缓存或现有持久化写入机制。
